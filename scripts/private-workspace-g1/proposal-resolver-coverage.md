# Isolated protocol and citation-proposal resolver prototype

This additive prototype exercises exactly `POST /api/protocols/proposals/[id]/resolve` and `POST /api/monitoring/proposals/[id]/resolve`. It is disconnected from the shared supplemental catalog and golden acceptance. It covers no private authorization, provider, rendered-byte or native-generator acceptance.

The fixture producer invokes the native snapshot registration and citation-status registration APIs against only the synthetic base six fixtures. It retains all generated IDs, timestamps and real evidence relations. Its 18 added rows are one ProtocolSnapshot, two ProtocolDriftProposal, two CitationStatusRecord, six ClaimUpdateProposal, three AuditEvent and four Notification. All existing rows remain exact. Each resolver has separate genuinely open targets for EDITOR and ADMIN. Other proposals remain open; the producer does not hand-write their histories.

The dedicated 132-request program runs all six principals, four invalid session recipes, first successful editor/admin resolution, repeated resolution, missing IDs, malformed bodies and foreign-origin controls. Every denied/repeated request must leave every allowed row and field, including all timestamps, exactly unchanged. The only successful domain changes are `status`, `resolvedById`, `resolutionNote`, and `resolvedAt` on the exact targeted proposal. Real handlers, Next request storage, real Prisma queries, transactions and native database constraints remain active. Every actual request cookie is checked against the production signer recipe and only its digest is retained.

The isolated grant proposal adds UPDATE on those four columns of ProtocolDriftProposal and ClaimUpdateProposal to the reviewed common runtime role. It grants no table-wide UPDATE or other authority. The child checks the actual complete role/table/column posture, NOINHERIT and absent membership/ownership/schema/private authority. Complete snapshots of all 72 common SELECT tables are compared after every request, and the standalone parent additionally checks all 87 table counts/rows.

A separate finite audit-input fixture supplies only absent AuditEvent `id` and `createdAt` fields for exactly four successful resolutions, preserving explicit values and rejecting unknown actor/action/subject tuples, extra fields, nested, bulk and non-audit creates. The native query executes exactly once. This conditional evidence excludes the native CUID and database-clock generation of those two audit fields; neither is mocked or claimed deterministic. The already reviewed Date-only fixture supplies domain `resolvedAt`. The production code and existing audit fixture are unchanged. No state field or HTTP body is excluded or normalized.

Native producer creation timestamps can be later than the fixed JS resolution clock. This is the retained actual split between native database time and the synthetic JS Date input, not a rewritten timeline or native-clock acceptance. The selected operations have no `@updatedAt` domain column, which avoids the separate native-clock obstacle found for fresh comment removal.

Source, actual restricted-role native captures, fresh-reset repeat equality, full-state proof and the proposed grants require independent review before parent integration. No shared catalog, golden, production schema, provider or deployment changes are included.
