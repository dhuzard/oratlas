# Standalone existing-notification resolution prototype

This unwired program adds one candidate POST method, editorial federation notification resolution. It is not in the shared program catalog, has no accepted golden, and does not complete G1. No production, database schema, shared fixture, or global grant declaration changes.

The native `receiveFederationNotification` producer parsed two synthetic COAR Notify RequestReview activities and emitted two pending inbound rows plus two receipt audits. The SQL supplement preserves all four emitted rows, native identifiers, actual database-default timestamps, payload bytes/hashes and platform version. The retained inert producer source and JSON are provenance, not a replacement implementation. Their source payload comes from the existing synthetic read fixture: its `g1-read-queue-private-payload` summary is an ordinary synthetic string, not private-workspace data. No URL is dereferenced.

The restricted child executes the native POST handler, shared same-origin/session/body/rate-limit plumbing and native resolution transaction. One EDITOR accepts the first request; one ADMIN rejects the second. The only additional standalone role privileges are UPDATE of `FederationNotification.status`, `resolutionNote`, `resolvedById` and `resolvedAt` (16 existing plus four column privileges). Both resolution time values come from native JavaScript `new Date()` under the existing fixed-Date contract; this model has no `@updatedAt` default. No extra SELECT or general UPDATE/INSERT is granted.

The reviewed real DB factory is imported by relative source path and extended using the approved absent-AuditEvent-default fixture. The explicit app-DB import binding is installed and awaited before importing the route graph. A separate two-slot wrapper requires the exact expected actor, action, target, idempotency key and decision/note details before supplying only absent audit `id`/`createdAt`. Unexpected creates, metadata, bulk/nested writes or a third audit are refused before delegation. The native platform-version extension remains active; each query delegates once. No other model default is supplied.

The 88-request program covers all six actual signed-cookie principals, four invalid-session controls, invalid decision, missing target, existing outbound/already-resolved rows, same-payload repetition, Origin/Sec-Fetch-Site/media failures and eighteen public inbox/payload observers. Repeated semantic requests retain the same body/path and add a compiled inert `x-g1-observation: exact-replay` header solely to distinguish raw capture composite keys; the native handler ignores that header. The accepted resource and inbox expose the exact native stored activity; the rejected resource remains 404. A failed early observation with duplicate composite keys was retained as a refused run, without a golden.

Every request has complete 72-table snapshots immediately before/after. Independent expected rows permit only four fields on each of the two native notification rows and exactly two new resolution audit rows. All existing audit rows and all other rows/fields remain exact; denials and GET observers append nothing. Actual dispatched Cookie digests bind the captured recipes. Guards inspect response headers/decoded bodies, complete rows, capture and trace before value-bearing assertions or exclusive 0600 persistence; unexpected Set-Cookie/Location are refused. The closed child has no bootstrap/private/provider credentials, and an outbound guard records zero attempts. Parent-only all-87-table snapshots/counts independently preserve the native setup and mutation deltas.

Two independently reset local captures are preliminary standalone evidence. Shared integration must independently review this source/data, activate only the four explicit grants, run all four empty-private-schema labels, prove old HTTP/public rows unchanged, independently review authority-only metadata deltas, and manually accept a separate baseline. Fresh inbox receipt creation, outbound delivery, live peers/providers, workspace authorization, other mutations, rendered HTTP, operational sinks and timing are not proved by this program.
