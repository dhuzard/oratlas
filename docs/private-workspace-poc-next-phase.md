# Private-workspace PoC: next phase and test readiness

**Planning baseline:** `main` at `c7aa9b7`, including merged [#217](https://github.com/dhuzard/oratlas/pull/217) (offline source-credit adapters) and [#218](https://github.com/dhuzard/oratlas/pull/218) (unconnected identity-link foundations). This plan accompanies the proposed [ADR §15](./private-workspace-security-architecture.md#15-proposed-poc-owner-operated-model-and-hosted-researcher-testing-proposed--pending-owner-ratification). It implements nothing and ratifies no policy. **D11 remains provisional; ADR §14 and §15 remain proposals.** Merge of #216 is not ratification.

## How close are we to testing?

| Target                                               | Evidence-based assessment                                                                                                                                                                                |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Offline source-tool mapping                          | Available now: synthetic pinned fixtures, source-credit adapters and golden regressions merged in #217. Not a live private connector.                                                                    |
| Identity-link logic                                  | Available now: deterministic fake-store tests merged in #218. No production module imports the orchestrator; these tests do not prove database atomicity or live provider behavior.                      |
| Existing public archive workflows                    | Separate from this project: public GitHub login/review ingestion already has its own tests. Public MVP acceptance (#198/#199) is not established by these private-feature changes.                       |
| Local private-workspace browser test                 | Not ready: identity persistence/session adapters and the private storage, authorization and invitation runtime are still prerequisites. Offline projector tests are not workspace UI tests.              |
| Independent researchers on hosted private workspaces | Not authorized by this draft. Requires explicit scope approval, security evidence, privacy assessment of real account/security metadata, and the §15 notice/acknowledgement and enablement requirements. |
| Real private research                                | Blocked by existing counsel/DPIA and security gates. Under proposed §14.1, both G2 and G3 are needed before real private content or metadata; that proposal is not accepted here.                        |

There is meaningful reusable groundwork, but this is **not one disclaimer away from a private-workspace trial**. No delivery date or percentage-complete estimate is justified by the current evidence.

## Immediate recommendation

Start with **A (explicit owner decision sheet)** and a **bounded C/G1 harness specification**, while refining B's persistence/session contract against the existing foundation interfaces. Do not wire live identity callbacks or open private workspaces to external testers as a shortcut. Route implementation as separate reviewed tasks once their decisions and acceptance criteria are settled.

Legal/privacy work can proceed alongside engineering: identify the operator/contact, inventory data flows (including accounts/logs/providers), assign purpose-specific legal responsibilities and propose a justified retention/deletion schedule. Counsel/DPIA confirmation remains a separate requirement, not something an engineering PR can supply.
