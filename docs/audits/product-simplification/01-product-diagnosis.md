# ORAtlas product diagnosis

Audit date: 2026-10-28. Repository baseline: `c02db1bf55fce2bc5a98ea3c915a22e9885e30bc`. Research, audit and design only; no production implementation, schema, contract, issue or PR changes.

## Decision

**Make ORAtlas an evidence comparison workbench for researchers who need to reconcile specific claims across scientific sources. Start with public, already captured sources.** The reusable outcome is an inspectable comparison with exact source context, evidence, unresolved differences and attributable decisions. The graph, archive and verification machinery support that outcome.

The proposed broad knowledge workspace is **materially ahead of the current product**. It requires ingestion of notes and AI conversations, dependable cross-source comparison, workspace authorization and durable collaborative work. These are not available simply by renaming Explore. Conversely, the existing ledger is real enough to support a narrower public comparison experience without rebuilding the backend.

This is a recommendation, not a ratified product decision. Neither demand nor retention has been demonstrated. Compare it against the publication-verification proposition with researchers before committing to the private-workspace expansion.

## Evidence conventions

- **V — verified finding:** inspected implementation, recorded local behavior or an explicitly attributed external issue report. Source inspection proves implementation presence, not deployment readiness.
- **I — reasoned inference:** consequence of the inspected design; not a measured user reaction.
- **H — product hypothesis:** proposed value or behavior requiring user validation.
- **R — recommendation:** an action based on V/I/H; it does not authorize implementation.

These labels apply throughout the package. Maturity and UX complexity in [02](02-feature-inventory.md) are judgments with separate evidence fields. No traffic, usage, research findings or production acceptance results are invented.

## Observed UX, with limits

The local app rendered 13 route/query cases successfully, plus the synthetic publication detail. See [browser observations](evidence/browser-observations.json). Screenshots directly inspected: [home](evidence/home-desktop.png), [scoped Explore](evidence/explore-scoped-desktop.png), [mobile Explore](evidence/explore-mobile.png). Other captures are supporting artifacts, not proof that every screen was visually reviewed.

- **V:** homepage prioritizes an explanatory verification proposition and synthetic publication. The seeded review corpus is elsewhere under “Legacy review archive.” **I:** “legacy” understates useful existing content before a replacement outcome exists.
- **V:** scoped Explore repeats the selected records as introductory links, graph nodes and detailed cards. On the captured mobile case the full document is 5,841px high; no document-wide horizontal overflow was measured. The graph has its own horizontal viewport. **I:** responsive containment works, but the comparison task still requires extensive traversal.
- **V:** empty Explore explains its scope boundary but does not immediately show a useful worked result. Claims' no-match state states the absence without a recovery action. **R:** a clearly labeled example and clear-filters action; never fabricate matches.
- **V:** semantic headings, labels, skip link, details disclosure, an accessible list alongside the graph and axe/viewport tests already exist. **R:** reuse them. This audit does not justify a cosmetic theme replacement or claim a comprehensive accessibility failure.
- **V:** verification and certification views are distinct, as they should be scientifically. **R:** expose them within source/claim context instead of requiring novices to choose a record type first.

Detailed interaction checks and accessibility results are in the [evidence record](evidence/README.md). There was no participant study, production browser inspection, screen-reader study, live verifier execution, live provider call or sensitive-data import.

Additional browser checks completed: anonymous deterministic Q&A, a legacy review-to-claim-passport traversal, and dev mock editor sign-in. The last revealed an editorial screen spanning synthesis, TRUST, submissions, lifecycle, challenges, proposals, monitoring, federation and audit. These observations confirm rendered behavior, not successful end-to-end publication or review mutations.

## Documentation drift and uncertainty

README navigation differs from the current layout. PLAN calls the original wizard five steps; `SubmitWizard` defines six. `docs/poc-limitations.md` describes a single LLM provider, while current discussion and graph-curation code accept transient Anthropic/OpenAI configurations. These documents are context, not authoritative evidence of today's UI behavior.

[UI_UX_RULES.md](../../../UI_UX_RULES.md) is a normative contract, not just descriptive documentation: it calls for review-first navigation, didactic visual Explore, and first-class machine access. The running header already differs from its Reviews/Explore/Compare/Create & deposit list. This audit deliberately proposes a reviewed revision of its primary positioning and graph-default requirements, as requested by the audit brief; it does not silently supersede that file. Preserve its identity, public-read, agent-access, scientific-governance and safe-rendering invariants. Its required graph snapshot/change-feed journey is still represented by open [issue 178](https://github.com/dhuzard/oratlas/issues/178), not proven by this audit's navigation check.

No feature is labeled unused on the basis of absent telemetry. “Legacy” is a current UI label, not evidence that reviews are obsolete. Missing private UI is confirmed; lack of a universal paid market is unknown. Proposed REMOVEs apply to redundant controls or claims of capability, not persisted scientific records.
