# Unwired AuditEvent default-input fixture

Plan and implementation boundary: main `449c47e`, synthetic PostgreSQL only. The existing T-PUB specification permits fixed clocks/IDs while retaining exact raw output. This prototype supplies only absent `AuditEvent.create` id/createdAt arguments through a real native Prisma query extension. It changes no production source, ID factory, engine, globals, triggers, schema, permissions, authentication or shared G1 program/golden.

The unchanged native `getPrisma()` factory retains its existing platformVersion query extension. An explicit test-only app-db import binding supplies that actual client, extended only in the fixed-input mode, to the unchanged audit writer. Both unextended controls use the same import seam. Every supported query executes once; explicit metadata/business input remains unchanged. Unknown, nested, bulk and upsert creates are refused before the engine. Other supported native operations receive unchanged arguments; this is not a general transaction or metadata clock replacement.

Native probe plan: two independently reset unextended children preserve real CUID/default-time variance. Two independently reset fixed-input children must append identical complete AuditEvent rows, preserve native platformVersion, exercise the actual audit utility and an interactive transaction, retain an explicit id/time unchanged, and compare every public row/field. Rollback, duplicate, foreign-key, role and append-only boundary controls must retain their native attribution; fixture refusals must not be mislabeled as PostgreSQL denials. Existing role grants only. Parent-only bootstrap/reset, no private tables/provider, pre-persistence capability checks and separate reviewed evidence are required. The executed result and exact evidence hashes are recorded below.

This proof does not cover comments, other models, createMany, upsert, updateMany or engine-generated updatedAt. Fresh comments additionally perform lifecycle-lock updates and bulk notification inserts, so this create-only fixture cannot establish their raw/full-state determinism. Non-HTTP/timing obligations remain separately tracked under the unchanged ADR gates; this unwired proof passes no G1 or populated-private matrix.

Executed native evidence (2026-10-21): four independently reset children passed under the same restricted public role, 72 public SELECT tables and the merged 16 column UPDATE grants. The parent compared all 87 inventory tables before/after every run: exactly three AuditEvent inserts, with every other row/field unchanged. Both generated IDs and database-default createdAt values differed between the two unextended runs. The fixed-input full proof bytes matched exactly (SHA-256 `29b1bbf8b750c1a2c7e2c1f3a215b6003d5281fef8bdb0200bab423cca237f91`), including raw complete rows, measured authority, query trace and outcomes. No fields were excluded or normalized.

The actual audit writer and interactive transaction retained native platformVersion `0.1.0`; explicit id/time stayed unchanged. Native unique/FK controls returned P2002/P2003, raw public UPDATE returned PostgreSQL 42501, and the interactive transaction rolled back. Five unsupported-create controls were refused by the fixture before a native query. All eight supported model-query callbacks delegated exactly once; outbound calls were zero. This counts model callbacks, not lower-level transaction wire commands.

AuditEvent has no UPDATE/DELETE immutability trigger in the checked-in schema. Its runtime INSERT/SELECT grants prevent modification; an administrator can UPDATE. A separate administrator transaction successfully changed a synthetic row then rolled back, and all 87 tables returned exactly to their prior values. This is an explicit authority limit, not an append-only database-guard pass.
