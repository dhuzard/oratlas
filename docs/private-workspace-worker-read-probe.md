# Synthetic worker read supplement

This is an additive handler-level G1 program, separate from the original public program and golden. It exercises four existing worker-only GET methods with native authentication, native stored packets/captures and real restricted PostgreSQL. It does not start a worker, contact a provider, submit results or introduce private workspace tables. Full G1 acceptance remains unresolved.

`workerReadScenarios()` declares 270 requests: 45 cases for each of the six existing user-cookie principals. Worker authority is independent of the cookie principal. The expected statuses are 24 successes, 96 unauthorized, 126 forbidden and 24 not-found responses. Each principal has a populated success for verification input, verification source artifact, certification run and certification input. These four methods already appeared in the public program with denial-only evidence; this supplement supplies positive authority coverage.

Credential controls include wrong owner, insufficient read scope, expiry at the fixed clock, revocation, inactive service identity, incorrect hash and unknown prefix. Verifier controls additionally exercise missing/wrong lease, lease expiry at the fixed clock, a terminal run despite a future lease, missing run and a capture outside the run's frozen artifact set. Certification reads use the existing completed native fixture run: their contract requires the owning certifier and read scope, without a verifier lease. Exact native error messages and populated results are declared independently of golden bytes. Each nonanonymous result must equal its anonymous-cookie counterpart.

## Native fixture and authority

Load the six reviewed base SQL fixtures, then the two files exported by `WORKER_READ_FIXTURE_FILES`, in their declared order. `WORKER_READ_FIXTURE_DELTAS` declares 37 additional rows. `worker-source-fixtures.sql` isolates a new publication/version and actual UTF-8 manifest/source captures, preserving the reviewed native MyST 0.3 declarations and exact source metadata. `worker-input.json` was emitted by the production packet builder for that subject, then frozen into the three verification runs. Offline tests validate its native schema and both packet digests; the real child independently rebuilds it through `getPublicationVersionPacket` and requires exact equality. Lifecycle fixtures retain the native 300-second lease duration and matching immutable lease hashes/events.

The two extra SELECT dependencies are `CertifierCredential` and `VerifierCredential`. The only extra UPDATE grants are their `lastUsedAt` columns, exported in `WORKER_READ_COLUMN_UPDATES`. There are no worker run/result/lease write grants. The actual application role retains its complete reviewed public authority, verified against shared grant definitions plus this supplement; this is not a claim that the application role is read-only. The child also refuses elevated flags, memberships, ownership, public schema CREATE and private schema access.

Successful authentication stamps `lastUsedAt` before downstream ownership/lease/subject checks. Therefore some denied requests legitimately stamp the authenticated credential. Every request asserts the complete before/after rows of all 12 synthetic credentials, allowing only the identified credential's fixed-clock stamp. The sidecar retains all those rows and every request transition. A deterministic full-row database digest covers every permitted public table, excluding only credential `lastUsedAt` already asserted and captured separately. Row ordering uses byte collation. No changed row count can hide a changed field.

## Capture contract and limits

Run the dedicated `worker-reads.g1.spec.ts` with the closed public child environment, absolute `G1_WORKER_CAPTURE_OUT`, and one of `baseline`, `baseline-repeat`, `after`, `after-repeat` in `G1_CAPTURE_LABEL`. It writes the HTTP capture and `<out>.state.json`. The sidecar contains no run label or elapsed wall-clock data, allowing exact state comparisons across all four labels. Private-schema existence is asserted according to the label, while its varying existence flag is not presented as identical evidence.

Worker recipes and digests of actual native Request header values bind dispatched authority. Raw bearer/lease values and secret components are refused before capture or child log persistence; neither request headers nor body-exclusion diagnostics store them. Fixture credentials contain hashes/prefixes only. These are deterministic public synthetic credentials, not production secrets.

The standalone probe demonstrated two fresh restricted-role captures with all 270 outcomes, exact paired responses and byte-identical complete credential sidecars. That evidence alone does not establish the parent runner's four-label before/after private-schema comparison or authorize a new golden. The parent owns reset, role grants, all four fresh children, manual supplemental golden review and lifecycle cleanup. Rendered pages, worker mutations/execution, other operational channels and full G1 remain separate obligations.
